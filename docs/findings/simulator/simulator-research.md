# Combat simulator research: what is established, what is not (2026-10-20)

Purpose: the facts a combat simulator (and any learned AI trained in it) can be built on, with the corrections made along
the way. Work lives in the local simulator repo (not published): its design notes are the full running log, its simulator handover is the running handover, and the local `opus-review` report is the audit that decides what to trust. Tags: **[code]** read in the 1.163 decompile,
**[data]** measured from telemetry, **[fit]** fitted, **[guess]** unproven. Details of single mechanisms are in the notes
linked below; this page only collects and cross-checks them.

## Physics (the game uses Box2D, see [box2d-physics-setup.md](../physics/box2d-physics-setup.md))
* Step 0.02 s (1/50), 10 iterations, gravity 9.82 game units (+y down), position scale 0.05, linear and angular damping 0.05, friction 0.6, restitution 0.001 [code].
* One convex polygon fixture per part from the `Mesh` in each Body node (<= 8 vertices); mass = min(w,h) x m_density x polygon area = seria `m_mass`; inertia is Box2D's own [code].
* The moving mass is `cmass` (creature +0x15b8, the sum of all part masses), not the logged `frame_mass`: jointed parts (engines, guns on slot types 146/162/282) are separate bodies that the Frame drags. a = F / cmass [data, 3 designs].
* Drag: Box2D damping gives 0.05/s. The game's quadratic air-drag force exists (F = -v_hat x 0.5 x 1.29 x c x |v|^2) but `c` = save key `m_drag_lin` is set only on level objects (City, Land, Town), never on ships, so hulls have none [code + file]. The measured coefficient also grows with speed (0.06 at rest, 0.27 at 400 u/s); that term is therefore not drag and is unexplained: a speed falloff of engine force or a measurement artefact; an engines-off high-speed coast would settle it.
* **CORRECTION 2026-10-21 [code]: hulls DO have a hardcoded quadratic air drag.** The Frame (class 0x1f) branch of `Body_PreStepUpdate` (`0x14001d440`, Body vtable `+0x168`, run for every live body before each `b2World_Step`) applies `F = -v_hat x A x min(W,H) x |v|^2 x 1.29 x 0.5` with `v` = Frame `+0x130/+0x134`, `W,H` = Frame bbox `+0x218/+0x21c`, `A = |H(-sin th n.x + cos th n.y)| + |W(cos th n.x + sin th n.y)|` (silhouette across the velocity, `th` = Frame `+0x138`, `n` = v_hat rotated -90 degrees), through `Body_AddForceAtPoint` at the Frame point `+0x210/+0x214`, so it also makes a torque about the COM that depends on the hull angle relative to the velocity. This is the speed-dependent term the audit found (a = -C2 |v| v); the statement above that hulls have no drag is wrong for Frames (it holds for the `m_drag_lin` branch only).

## Engines
* Force per engine = Stats+0xf8 x strength x cos(command - engine angle), dropped if cos <= 0, along (sin a, -cos a) ([contact-damage-and-fire.md](../combat/contact-damage-and-fire.md) has the surrounding handler) [code]. `eng_840` in the logs is a force readout (0.5 + 1e-8 x force), not a throttle [code + data].
* The engine angle (part +0x138) follows the command angle through a Box2D motor: speed = wrap(cmd - angle) x power^2 x Stats+0x108 (3.0, so tau = 1/3 s), max torque mass/100 [code]. It is logged in the simparts Q rows.
* Engine names: `MDL_ENGINE_01` RD-59 (swivel), `02` RD-59S (static), `03` D-30 (swivel), `04` NK-25 (swivel), `05` D-30S (static) (S = static; user). Swivel is data: `m_slot_type` 146/162 rotate, 1105/1121 are rigid. `06` has no placeable prototype.
* Fuel: two code paths. Every ship: Stats+0xd0 x eng_840 x dt x 50 (x50 under the arcade flags) while 0 < eng_840 < 1. Player-controlled ships also: Stats+0xd0 x (cos x strength)^2 x dt x 50 [code + data].

## AI
* The waypoint formula of `AiShipTick` (`0x140062f90`) is ported (`hfsim/ai/steering.py`, agreement at the 0.1-unit log resolution) [code + data].
* Force and bank pipeline (`AiShipTick` inline path, [ai-steering-and-avoidance.md](../ai/ai-steering-and-avoidance.md)): `F = ((dir + A) * s * cmd_max * m - v * m) / ts - (0, m * 9.82)` with `m = creature +0x15b8` (`cmass`), `accel = (T1 + T2) / (m * 9.82)`, `cmd_max = accel * 25` (`min(accel, 4) * 40` when `+0xc74` is set and `accel < 4`), `ts = 10 / min(accel, 4)`, `s = clamp(sqrt(dist + 0.1) / 20, 0, 1)`. There is no fixed `1.7` factor: attitude hold (`k = wrap(-angle) * I / 20` along `(sin a, -cos a)` when `turn_gate / I > 0.02`) splits `F` into two bank vectors, each snap-clamped (`(T, 2T] -> T`, `> 2T -> 2T`) and passed through a recursive 5-slot `/6` ring filter (`out = (V + 5 stored) / 6`, output stored; 1-tick lag). Obstacle avoidance (`AiShip_ScanObstacles` `0x14024cc20`, `w = ((10 - t) / 10)^2` over other ships' part bboxes and `lnd_brick` terrain bricks) is ported in `hfsim/ai/avoidance.py` [code + game].
* Enemy ammo doctrine is rolled once at spawn (first group-0 gun's calibre and rating): see [firing-and-shells.md](../combat/firing-and-shells.md) and [ai-tick-patch-sites.md](../ai/ai-tick-patch-sites.md). AP needs `c7c` AND `c74` AND `distance < 1000`; proximity needs `c7d` AND (`c75` OR `c76`) [code + game].

## Hull rotation, legs and heat (resolved 2026-10-21..23)
* **Built-in hull stabiliser:** `creatureLogic` case 200 (`0x140035652`, [hull-stabiliser-engine-logic.md](../physics/hull-stabiliser-engine-logic.md)) runs once per live engine part per step for both player and AI ships, applying `Body_AddTorque(Frame, clamp(Tw + Ta, -m_at, +m_at))` using stale pre-step `w` and `angle`, Frame-only `I_origin`, per-tick idle-bank halving (`Ta = 0, Tw *= 0.5` if either bank applied zero force that tick), and a ~30-tick (0.6 s) thrust-history gate (`+0x15b4`) [code + game].
* **Landing legs in flight:** each leg segment is a separate Box2D body held tucked against the hull on its folded revolute limit with a `10 Hz`, `dampingRatio = 10` distance strut ([landing-legs.md](../physics/landing-legs.md)); welding legs in the drawn pose inflates hull inertia by 4–10 % [code + game].
* **Engine heat, lockout and FSS:** engines gain `(g * strength)^2 * 70 * dt` per tick, decay by `-0.0016191 * T`, conduct `0.008 * (T - Tn)` downhill along `m_slots`, self-heat `+1.0/tick` while burning (`T > 400`, two `Body_BurnUpdate` calls: `0.8 + 0.2`), and lock out for `3.0 s` whenever `T >= 500` ([player-thrust-keys-and-engine-heat.md](../physics/player-thrust-keys-and-engine-heat.md)). Fire suppression (`Part_ExtinguishNearbyParts` `0x140033800`) resets **all** ship parts within `30.0` design units of remaining `MDL_FSS` modules to `T = 100`, `dose = 0`, `lock = 0` [code + game].

## Damage and kill
* Contact damage = 0.8 x the Box2D PostSolve maximum normal impulse, equal on both sides, gated by `Stats +0xc4` (`m_mdl_armor`); tear-off above impulse 4e6 (8e6 arcade) on Frame children has no damage call ([contact-damage-and-fire.md](../combat/contact-damage-and-fire.md)). Plain cannon shells arm after `20 / |v|` s (`+0x38c = 25 * mass`) and detonate via `Projectile_DetonateOnImpulse` (`0x14001d1e0`), dealing essentially all ship-part damage through their blast (`R = sqrt(E)`, owner factor `1.0` player / `0.66` AI, 360-bucket armour shadow table, no `Stats +0xc4` gate; [shell-detonation-paths.md](../combat/shell-detonation-paths.md), [blast-and-penetration.md](../combat/blast-and-penetration.md)) [code + game].
* Fire is a heat model; only fuel tanks and engines can burn.
* Ship removal rules (`ShipStatusCheck` `0x14006ab70`: engine bank sum 0, TWR < 1, fuel 0, power 0, parts ratio < 0.65 with `c48 == 0` or `rating <= 40`, no active gun) and bridge death (`KillAndQueueDead`) are documented in [ship-removal-and-battle-result.md](../ships/ship-removal-and-battle-result.md) [code + game].

## Corrections made during this work (do not repeat the old claims)
* "Thrust falls off with speed" - it is Frame quadratic air drag plus the swivel transient. "k = 0.879/0.807 delivered fraction" - it is the `frame_mass / cmass` ratio. "`lambda = 1.7` AI force multiplier" - replaced by the exact two-bank snap clamp + recursive 5-slot `/6` ring filter. "eng_840 is the throttle" - a force readout. "Engine angle equals hull angle" - false, the engine angle is its own logged field. "There is no gravity" - `9.82` (+y down). The old names RD-59 (static) / RD-59S (manoeuvre) were swapped.
* The 0.0087 deg waypoint match, the 0.004 deg servo angle and the 0.00 deg force reconstruction are measurement floors or self-comparisons, not accuracy.
* The first replays of the servo model used oracle inputs (logged hull angle every tick, logged initial engine angles); the current standalone simulator (`SIM_STABLE_V2`) models hull rotation, swivels, folded legs and heat closed-loop.

## Remaining simulator gaps
* High-spin (`5–11 rad/s`) trajectory drift on small 2-engine swivellers (float32 C++ Box2D vs float64 pybox2d + single-engine idle-bank boundary sensitivity).
* Continuous fuel-mass depletion, `< 100 %` power satisfaction (`P^2` servo scaling), campaign zoom-dependent `f(X)` thrust scaling, hull break-up fragments, missiles/planes/flares, and wiring the verified shell/blast primitives + gun/kill stubs (`hfsim/combat/`) into a live multi-ship combat loop.
